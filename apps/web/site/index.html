Memory

Persistent memory for Claude Code, Codex, ChatGPT, Grok, Grok Bot and OpenClaw.

Your agents already know how to work. What they lose is the thread between sessions. brunn is an MCP memory server that keeps it: a Claude Code session drops in a checkpoint at six, Codex draws it up at nine, Grok on your phone reads the same well at noon, a Grok Bot checks it on a schedule, and an OpenClaw agent works from it overnight.

  • memory.openOrient a fresh session: the relevant sources, the last checkpoint, what changed since.
  • memory.queryExact, keyword and semantic search across everything you've kept.
  • memory.readRead a pinned version, so a citation means what it meant.
  • memory.captureDrop in source material with provenance: a page, a thread, a file.
  • memory.checkpointLeave goals, decisions, open questions and next actions for the next agent.
  • secret.getUse credentials from an encrypted vault that never enters the corpus.

Morning briefing

One briefing every morning, already deduped.

Your agents do the research overnight. brunn holds the topics, remembers every story it has already told you, and publishes one edition to the web and your phone. Read it in thirty seconds; expand what matters.

  • Topics in plain prose. Tell any agent "add a section on Seattle air quality, June through October" and it's a topic.
  • Nothing twice. A story ledger drops repeats across days and flags real updates as updates.
  • Go deeper. Ask for more on any item; the answer lands in tomorrow's edition.
  • Your projects, your calendar, your numbers. The same edition carries what changed overnight in your own work.

Dreamer

While you sleep, the Dreamer reads.

Every night, a bounded research pass works through what changed: it keeps one dated overview per person, project and topic, links related notes, and proposes edits with the evidence attached. In the morning, you review. Nothing changes silently.

  • Best-known understanding, with an honest review date. Each overview says what it's reviewed through and what's still open.
  • Every claim pinned to a source version. Contradictions are surfaced, not smoothed over.
  • A review window you control. Approve, reject, defer, or correct. Unrejected proposals go live after the window you set.
  • A knowledge wiki, kept for you. It's a version of the knowledge-wiki pattern: raw sources stay untouched, and the overviews that compile them link to each other and back to the evidence.
  • Questions when it isn't sure. Answer in the app, or just tell an agent.

How it connects

Three steps to connect.

brunn is one hosted MCP endpoint with OAuth. Each client, from Claude Code to a Grok Bot, gets its own credential, and you can revoke any of them without touching the others.

Connect a client

Add the endpoint to Claude Code, Codex, ChatGPT, Grok, OpenClaw or any MCP client and approve it once.

$ claude mcp add --transport http brunn \
    https://brunn.ai/mcp
$ codex mcp add brunn --url https://brunn.ai/mcp

Work as usual

Agents open the well at the start of a task, read exact sources as they go, and leave a checkpoint when they stop.

› memory.open   task: "…"
› memory.read   path, version
› memory.checkpoint

FAQ

Common questions.

What is brunn?

One memory and workspace for all your agents: a durable, portable place where the AI agents you use drop in what they learn and draw it back up later. It holds source material, checkpoints, tasks, briefings, files and credentials in one well that Claude Code, Codex, ChatGPT, Grok, Grok Bot, OpenClaw and any MCP client can open. It is a place and a thing, never an AI of its own.

Is brunn an MCP memory server?

Yes. brunn serves persistent memory for AI agents over one hosted Model Context Protocol endpoint, so the same memory works for Claude Code, Codex, ChatGPT, Grok, Grok Bot and OpenClaw without a plugin per tool.

It is more than an agent memory store. Every answer is drawn from exact source versions, sessions leave checkpoints a fresh agent can resume, and the same well feeds the morning briefing, the task list and the Dreamer.

Which agents and tools work with it?

Anything that speaks the Model Context Protocol. brunn exposes one hosted, OAuth-protected MCP endpoint at brunn.ai/mcp, so Claude Code, Codex, ChatGPT, Claude.ai, Grok, Grok Bot, OpenClaw and other MCP clients share the same memory, and you can switch between them mid-task. There is also an HTTP API, a local MCP adapter, the web app, and a native iPhone app for the briefing, tasks and alerts.

How is it different from a memory API like Mem0 or Zep?

Memory APIs store extracted facts for an application you build. brunn is the workspace for the agents you already use. Every answer is drawn from exact, versioned sources you can inspect. Sessions leave checkpoints a fresh agent can resume. And the same well feeds a morning briefing, a task list and a nightly Dreamer.

It is a version of the knowledge-wiki pattern: raw sources stay untouched, and agent-maintained overviews compile them, with a review step before anything changes. It is not a RAG layer, a knowledge graph, or an agent runtime.

Where does my data live?

Plain Markdown and your stored files are the source of truth; indexes and views are rebuilt from them. Export the whole well at any time as files and a manifest. The hosted service runs at brunn.ai. Credentials live in an encrypted vault outside the searchable corpus.

Is it open source? Can I self-host it?

Not yet. An open-source release is probable: the code is being cleaned up and the self-host path (a Rust API, PostgreSQL and S3-compatible storage under Docker Compose) made simple first. When it's ready, the repository will be linked from this page.

How do you say it?

One syllable, brun, rhyming with "put". From the Old Norse brunnr, a well: Mímisbrunnr, the well of memory beneath the world tree. Always lowercase.
