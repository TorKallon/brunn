# E04 — Result budget experiment

Status: Complete — negative result; D01 rejected

## Verdict

Retain the current Arm A retrieval behavior and ship neither candidate. Both
Arm B and Arm C passed the deterministic 640K and query-shape gates, and
neither caused a statistically significant work or personal guard regression.
Neither, however, met the primary RuptureOps tradeoff or the chronic-case
criterion:

- B reduced cluster-weighted RuptureOps service result characters by 1.26%,
  from 59,975 to 59,222, while passing 120/176 claims versus A's 133/176.
- C reduced them by 6.78%, to 55,908, while passing 128/176 claims.
- The acceptance target was a 25% reduction and no more than 53,100
  characters when quality did not improve significantly. Neither candidate
  reached it.
- In the two dedicated chronic draws, B had 3 wins, 4 losses, and 5 ties
  versus A; C had 3 wins, 3 losses, and 6 ties. The contract requires wins to
  exceed losses.
- B moved `star-rupture-plan-revision` from 2/5 complete passes under A to
  0/5. C moved `ruptureops-archive-import-reconciliation` from 3/5 to 0/5.

The frozen contingency predeclaration prohibits the under-specified factor
bisection in this execution. A future factor-isolation run would need a new
paired design, output contract, acceptance rule, and cost preflight.

## Integrity result

The complete set contains 52 JSON/Markdown artifact pairs and 528 agent
case-runs: 396 service runs and 132 filesystem runs. All 528 runs exited
successfully, none timed out, none retained a record error, and all 2,112 claim
slots were graded. Every run ledger records clean source provenance,
ChatGPT-subscription authentication, and forbidden API fallback. All 396
service runs bind the same image ID and revision.

The service records contain 34 local checkpoint-wrapper failures. Every one is
followed by a successful checkpoint HTTP operation in the same record, so the
final harness classifies them as recovered local CLI failures and excludes
them from service metrics. There are no unrecovered local failures and no
measured non-2xx service operations.

The no-repeated-zero audit found only three isolated zero-claim observations:
A `warmind-parser-learning` draw 1, B `star-rupture-plan-revision` draw 2, and
C `star-rupture-plan-revision` draw 3. No arm/case pair has zero claims in two
or more draws, and no case-run has a zero composite score. Forbidden assertion
hits are also zero.

The aggregate and accepted-source audit were independently rerun from all raw
inputs. Each reproduced its saved payload exactly apart from `created_at`.
